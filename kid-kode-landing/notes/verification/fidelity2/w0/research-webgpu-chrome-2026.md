## 1. Architecture patterns for GPU-rendered chrome over a live scene

### 1a. Single-canvas, in-scene chrome sampling the shared viewport texture — **FITS-TSL** (recommended)
The WebGPU-renderer-native pattern. Chrome quads are transparent meshes in the *same* scene/canvas, drawn after opaques; their materials read what was already rendered via `viewportSharedTexture()`. Per the [three.js TSL wiki](https://github.com/mrdoob/three.js/wiki/Three.js-Shading-Language), `viewportSharedTexture()` "accesses the beauty of what has already been rendered, preserving the render-order. This enables easy refraction effects, avoiding multiple render-pass and manual sorts." This is the only architecture where panels can truly refract the live scene with zero extra passes — a second transparent canvas physically cannot (it can't sample the other canvas's framebuffer).
- Canonical example: [three.js webgpu_backdrop](https://threejs.org/examples/webgpu_backdrop.html) ([source](https://github.com/mrdoob/three.js/blob/master/examples/webgpu_backdrop.html)) — `material.backdropNode = hue(viewportSharedTexture().bgr, ...)`, `material.backdropAlphaNode`, `material.transparent = true`. Also [webgpu_backdrop_water](https://threejs.org/examples/webgpu_backdrop_water.html) for depth-aware refraction.
- Z-order: put chrome in a `THREE.Group` with high `renderOrder` + `depthTest:false` (or parent it to the camera). The classic two-pass HUD alternative (`renderer.autoClear=false; render(scene,cam); renderer.clearDepth(); render(hudScene, orthoCam)`) is documented on the [three.js forum HUD thread](https://discourse.threejs.org/t/ui-hud-how-to-blend-orthographic-with-perspective/21518) and [Evermade's Pure Three.js HUD](https://www.evermade.fi/story/pure-three-js-hud/) — but `viewportSharedTexture` refraction works in the single-pass transparent-after-opaque ordering, so prefer renderOrder over a second `render()` call.
- Shipped precedent for full-GL chrome: **Igloo Inc** ([Awwwards SOTY 2024 case study](https://www.awwwards.com/igloo-inc-case-study.html), [technical breakdown](https://www.webgpu.com/showcase/igloo-inc-procedural-crystals/)) rendered the *entire* UI in GL — "text glitches are handled via shaders, and letter scramble effects swap SDF texture offsets instead of forcing the browser to relayout DOM elements on every frame." Performance optimization and creative surface in one. Your MSDF stack (`three-msdf-text-webgpu`) is the same class of approach.

### 1b. DOM-rect → GPU-quad alignment — **FITS-TSL** (small math layer, no adaptation)
The shipped pattern across Codrops tutorials and 14islands' production rig: CSS owns layout; `getBoundingClientRect()` is mirrored into mesh transforms.
- [14islands r3f-scroll-rig + lens refraction tutorial](https://tympanus.net/codrops/?p=73607) (David Lindkvist, Codrops): fixed full-viewport `<GlobalCanvas/>`, `<ScrollScene>` "measures and tracks DOM references, synchronizing WebGL mesh position and scale to matched HTML elements," DOM proxies kept for semantics/a11y, Lenis for scroll, `ImageBitmapLoader` for off-main-thread texture upload. [Repo](https://github.com/14islands/codrops-scroll-rig-tutorial).
- Same rect→NDC→world conversion in [Codrops: From DOM to WebGL parallax gallery (Feb 2026)](https://tympanus.net/codrops/2026/02/19/creating-a-smooth-horizontal-parallax-gallery-from-dom-to-webgl/) and [responsive SEO-friendly WebGL text (2025)](https://tympanus.net/codrops/2025/06/05/how-to-create-responsive-and-seo-friendly-webgl-text/).
- **Implementation-ready recipe for an editor (not a scroll page):** give the chrome group its own orthographic projection mapped 1:1 to CSS pixels (`left=0, right=cssW, top=0, bottom=-cssH`); each dock/panel/flyout has an invisible DOM twin (paint suppressed) that owns layout, focus, text input, and pointer events; `ResizeObserver` + rAF read of `getBoundingClientRect()` writes `position=(rect.x, -rect.y)`, `scale=(rect.w, rect.h)` into instanced attributes. **Quantize rects to physical pixels** (multiply by DPR, round) or SDF edges shimmer during panel animation.
- Pointer events, two viable models: (1) **DOM owns input** — DOM twins with `background: transparent` sit on top (scroll-rig model; native focus/hover/a11y free); (2) **GL owns input** — raycast quads and emit W3C-compatible events via [@pmndrs/pointer-events as used by uikit](https://github.com/pmndrs/uikit) (Igloo model). For an editor with text fields and sliders, model (1) is strictly less work: CSS `:hover`/`:active` states become uniform writes.

### 1c. Separate transparent canvas / DOM-snapshot glass libraries — **ADAPT (reject for this build)**
The 2025 "liquid glass" wave ([liquidGL](https://github.com/naughtyduk/liquidGL), [liquid-glass-js](https://github.com/dashersw/liquid-glass-js), [html-liquid-glass-effect-webgl](https://github.com/rxing365/html-liquid-glass-effect-webgl), survey at [lucky.graphics](https://lucky.graphics/learn/liquid-glass-css-glassmorphism-tutorial/)) refracts a *DOM snapshot* (html2canvas-class capture) in a second canvas. Two disqualifiers: snapshots are static (can't refract a live animating scene) and snapshot libs are in the forbidden-dependency class (`html-to-image` ban). Their *shader recipes* (edge-weighted displacement, RGB-channel chromatic aberration, cursor-tracked highlights) are still worth mining — see §3/§4.

## 2. SDF-based UI chrome in shaders

### 2a. Rounded-rect SDF + screen-space-derivative AA — **FITS-TSL**
Production-proven in GPU-native editors: [Zed's GPUI blog](https://zed.dev/blog/videogame) (120fps, per-primitive shaders, SDF rounded rects via "shrink rect by radius, subtract radius from distance") and [Warp's Metal rectangle writeup](https://www.warp.dev/blog/how-to-draw-styled-rectangles-using-the-gpu-and-metal) (~300 LOC for the full styled-rect primitive, borders by quadrant-dependent corner shrink). The SDF is Inigo Quilez's `sdRoundedBox`; per-corner radii pack into a `vec4` instanced attribute.
- AA best practice: width from `fwidth(d)`, i.e. `alpha = clamp(0.5 - d / fwidth(d), 0, 1)` or `smoothstep(w, -w, d)` with `w = fwidth(d) * 0.5` — never a fixed epsilon. References: [Drew Cassidy on SDF antialiasing](https://drewcassidy.me/2020/06/26/sdf-antialiasing/), [shadergif AA basics](https://shadergif.com/guides/anti-aliasing-basics/), worked rounded-rect example in [Infinite Canvas Tutorial lesson 9](https://infinitecanvas.cc/guide/lesson-009), [SolidAlloy's SDF corners/borders series](https://medium.com/@solidalloy/drawing-rounded-corners-and-borders-with-sdf-part-1-rounded-corners-8017bb6ce6f9).
- TSL: maps 1:1 — `Fn()`, `abs/max/min/length`, and `.fwidth()` exist in [TSL](https://threejs.org/docs/pages/TSL.html). Compute `d` in CSS-pixel space (rect half-size, radius vec4, border width as instanced attributes), output coverage into `opacityNode`.

### 2b. Bevel normals from the SDF gradient → feed `normalNode`, get real Fresnel for free — **FITS-TSL** (keystone)
Instead of writing a BRDF, derive a 3D normal from the 2D SDF and hand it to `MeshPhysicalNodeMaterial.normalNode`. The renderer then gives true GGX speculars, Fresnel edge response, env reflections, anisotropy, and transmission against actual scene lights — no custom lighting code.
- For an analytic SDF the gradient is exact (direction from the clamped corner point) — no texture taps, unlike texture-SDF systems that reconstruct normals from 4 samples ([Catlike Coding SDF toolkit bevel docs](https://catlikecoding.com/sdf-toolkit/docs/shaders/)). Cheap alternative: `grad = vec2(d.dFdx(), d.dFdy())`.
- Bevel profile: `t = smoothstep(-bevelWidthPx, 0, d)` (or circular fillet `sqrt(1-(1-t)²)`), then `normal = normalize(vec3(grad * slope(t), 1))`. Flat face → `(0,0,1)`; edges roll over → grazing angles → Fresnel rim appears automatically. The same `t` doubles as a thickness map for §3 lensing.
- Micro-normal materials: `MeshPhysicalNodeMaterial` under WebGPU supports the full physical set — `anisotropy`/`anisotropyRotation` (brushed metal streaks), `clearcoat` (ceramic), `roughnessNode` driven by tiling noise ([MeshPhysicalNodeMaterial docs](https://threejs.org/docs/pages/MeshPhysicalNodeMaterial.html), [anisotropy discussion](https://discourse.threejs.org/t/how-to-apply-brushed-metal-anisotropy-on-meshstandardmaterial/32945)). Brushed metal = `metalness 1`, `roughness ~0.35`, `anisotropy ~0.8`, rotation aligned to the dock's long axis.

### 2c. Shadows, borders, batching — **FITS-TSL**
- Drop shadows: [Evan Wallace's fast rounded-rectangle shadows](https://madebyevan.com/shaders/fast-rounded-rectangle-shadows/) — closed-form Gaussian (error function) along one axis, small fixed sample count along the other; constant-time, single quad, adopted by [VLC's Qt UI](https://code.videolan.org/videolan/vlc/-/merge_requests/7198). Port the erf approximation into a TSL `Fn`. Analysis: [Raph Levien — blurred rounded rects](https://raphlinus.github.io/graphics/2020/04/21/blurred-rounded-rects.html).
- Batching discipline from [pmndrs/uikit](https://github.com/pmndrs/uikit) ([perf docs](https://pmndrs.github.io/uikit/docs/advanced/performance)): instanced panel quads; "the amount of different Material Classes used directly influences the amount of draw calls," each font family = +1 draw call. Translation: one instanced mesh per chrome material family (glass, metal, ceramic), style variation via instanced attributes, never per-button materials. uikit itself is WebGL-oriented — reference architecture (**ADAPT**), not a dependency.

## 3. Glass / refraction UI (refracting the live scene)

### 3a. Native transmission on `MeshPhysicalNodeMaterial` — **FITS-TSL** (zero-custom-code baseline)
Set `transmission`, `ior`, `thickness`, `roughness`, `dispersion`, `attenuationColor/attenuationDistance`; the WebGPU renderer renders opaques into a shared **viewport mip texture** and the transmission lobe samples it with roughness→mip-LOD blur — the roughness blur mip chain is built in. Per the [TSL docs](https://threejs.org/docs/pages/TSL.html), `viewportMipTexture()` is the viewport texture node "with enabled mipmap generation," intended for transmissive materials; the transmission backdrop "defaults to the renderer's viewport mip texture."
- **Smoked glass recipe:** `transmission 1, ior 1.45–1.5, thickness 2–6 (slab), roughness 0.15–0.35, attenuationColor #2a2018, attenuationDistance ~4` → Beer–Lambert tint darkening with thickness; §2b bevel normal makes edges both lens and catch Fresnel. `dispersion` gives spectral edge fringing without custom samples.

### 3b. Custom `backdropNode` refraction — **FITS-TSL** (cheapest, most art-directable; use for most chrome)
For thin UI slabs full Snell is overkill. Maxime Heckel's TSL glass ([Field Guide to TSL and WebGPU](https://blog.maximeheckel.com/posts/field-guide-to-tsl-and-webgpu/)) uses a normal-driven UV shift: `refractNormal = normalWorld.xy * (1 - normalWorld.z * 0.85)`, sampling the scene at `viewportUV - refractNormal * strength`. With the §2b bevel normal this *only displaces near edges* — precisely the Apple liquid-glass lensing look ([liquid-glass shader writeups](https://dev.to/maxgeris/webgl-based-javascript-library-for-pixel-perfect-ios-liquid-glass-effect-with-refractions-and-3p8m) confirm edge-weighted displacement + RGB-offset aberration is the whole trick).
- Use `viewportSafeUV(uv)` when displacing: depth comparison that "mitigates visual errors when using viewport texture nodes for refraction" ([TSL wiki](https://github.com/mrdoob/three.js/wiki/Three.js-Shading-Language)) — prevents foreground objects smearing into the panel.
- Dispersion: 3 samples (R/G/B at slightly different shift scales). Full recipe with per-channel IORs, sample loop, and the saturation-loss fix (mix toward saturated using luminance `0.2125/0.7154/0.0721`) in [Maxime Heckel — Refraction, dispersion, and other shader light effects](https://blog.maximeheckel.com/posts/refraction-dispersion-and-other-shader-light-effects/). He warns the sample loop is the bottleneck — keep it at 3 (one per channel), max 6; skip his two-pass backside trick (meaningless for flat slabs, costs an extra scene render).
- Frosted blur: `viewportMipTexture(uv).level(roughnessFactor * maxMip)` — one trilinear tap against the existing pyramid. Reserve the [`gaussianBlur` TSL display node](https://threejs.org/docs/pages/GaussianBlurNode.html) (a *double render-pass*) for cases where mip blockiness is unacceptable; never per panel.

### 3c. Drei `MeshTransmissionMaterial` and its TSL port — **ADAPT / FITS-TSL respectively**
[drei's MeshTransmissionMaterial](https://github.com/pmndrs/drei/blob/master/src/core/MeshTransmissionMaterial.tsx) defined the look (anisotropicBlur, chromaticAberration, distortion, backside) but is GLSL/WebGL with optional per-material FBO buffers (**ADAPT** — N panels = N scene copies; avoid). Direct fit: [`MeshTransmissionNodeMaterial` from @three-blocks/core](https://www.threejs-blocks.com/docs/MeshTransmissionNodeMaterial) — TSL node material extending `MeshPhysicalNodeMaterial`, WebGPU+WebGL, defaulting to the renderer's shared viewport mip texture (no per-panel buffers), with `chromaticAberration` (default 0.4), `anisotropicBlur` (0.38), noise `distortion`/`temporalDistortion`, Beer–Lambert `attenuationDistance`, blue-noise `ditherStrength`, and `forceSinglePass: true` "for better visual and performance results." Use directly or crib the node graph. Background TSL glass tutorials: [Codrops — procedural vortex in a glass sphere with TSL (2025)](https://tympanus.net/codrops/2025/03/10/rendering-a-procedural-vortex-inside-a-glass-sphere-with-three-js-and-tsl/), [Codrops — glass torus with MeshTransmissionMaterial (2025)](https://tympanus.net/codrops/2025/03/13/warping-3d-text-inside-a-glass-torus/).

### 3d. <2ms reality check
Achievable if: (a) all glass panels share ONE viewport copy + mip-gen per frame (`viewportSharedTexture`/`viewportMipTexture` are shared by design — flat cost regardless of panel count); (b) per-pixel work is 3–4 texture taps (RGB dispersion + 1 mip tap), no loops; (c) chrome coverage stays toolbar-thin (cost is fill-rate × covered pixels); (d) DPR capped at 2 (Maxime's explicit advice). Mip-chain generation of the full-res copy is the dominant fixed cost — if timestamps blame it, refract from a half-res copy (precedent: drei's `resolution` prop).

## 4. Pointer-reactive lighting

### 4a. Cursor as a real scene light — **FITS-TSL** (zero shader code)
Because §2b chrome uses `MeshPhysicalNodeMaterial` with real normals, the cheapest award-grade move is a real `THREE.PointLight` (small `distance`, warm tint) at the pointer ray's intersection with the chrome plane, slightly in front. Every bevel, brushed-metal streak, and glass rim responds with physically-correct speculars — including the anisotropic elongated streak on brushed surfaces ([anisotropy refs](https://discourse.threejs.org/t/how-to-apply-brushed-metal-anisotropy-on-meshstandardmaterial/32945)). Smooth the light position with a damped spring (GSAP `quickTo` / `MathUtils.damp`) so highlights trail the cursor — perceived expensiveness is mostly this easing.

### 4b. Pointer uniform inside the SDF shader — **FITS-TSL**
Pass pointer position in CSS-pixel space as `uniform(vec2)`:
- **Specular streak:** Blinn-Phong against the bevel normal with light dir toward pointer — `pow(dot(n, halfVec), shininess)` ([point lighting — WebGL Fundamentals](https://webglfundamentals.org/webgl/lessons/webgl-3d-lighting-point.html), [ndesmic's specular walkthrough with mouse-as-light](https://dev.to/ndesmic/webgl-3d-engine-from-scratch-part-10-specular-lighting-1gl8)). For a streak, elongate the falloff along the surface tangent (anisotropic Gaussian on the half-vector).
- **Magnetic edge highlight (Linear-style border glow, GPU edition):** reuse the SDF — `borderBand = 1 - smoothstep(0, borderPx, abs(d))`, multiply by radial falloff `exp(-distSq(pointer, pixel)/σ²)`, add into `emissiveNode`. The glow slides along rounded corners for free because it's the same distance field.
- **Hover/press states:** drive uniform floats from the DOM twins' pointer events, written imperatively — no React re-render ([uikit perf guidance](https://pmndrs.github.io/uikit/docs/advanced/performance) on signals/refs vs reconciliation).
- Cursor-tracked refraction+specular is exactly what the [liquid-glass shader libraries](https://dev.to/jqueryscript/liquid-glass-shader-webgl-powered-ios-style-glass-effects-for-javascript-3lek) ship at 60fps; for trail/inertia buffers see [Codrops — interactive mouse effect with instancing](https://tympanus.net/codrops/2023/12/13/creating-an-interactive-mouse-effect-with-instancing-in-three-js/). Shipped award reference: [Dorian Lods portfolio — WebGL refraction hover (Awwwards 2025)](https://www.awwwards.com/inspiration/webgl-refraction-hover-effect-dorian-lods-portfolio-2025); Igloo Inc's hover glitches are SDF texture-offset swaps.

## 5. Perf: ~2ms chrome on M-series, 60fps with a photoreal scene underneath

- **Measure on-GPU, not rAF deltas:** three's WebGPU renderer has first-class timestamp queries via [TimestampQueryPool (PR #30359)](https://github.com/mrdoob/three.js/pull/30359) with `THREE.TimestampQuery` constants ([PR #30375](https://github.com/mrdoob/three.js/pull/30375)) and `resolveTimestampsAsync` per render/compute context. Easiest harness: [stats-gl](https://github.com/RenaudRohlinger/stats-gl) (WebGPU GPU-ms panel, [demo](https://stats.renaudrohlinger.com/webgpu.html)) — note a [compat break at r181](https://discourse.threejs.org/t/webgpu-r181-fyi-stats-gl-no-longer-compatible-with-webgpu/87944), pin versions. **Safari/WebKit lacks timestamp queries** ([three.js #30571](https://github.com/mrdoob/three.js/issues/30571)) — budget on Chrome/M-series, sanity-check Safari by frame pacing. Background: [webgpufundamentals timing](https://webgpufundamentals.org/webgpu/lessons/webgpu-timing.html).
- **Cost model** (each term independently controllable):
  1. *Shared viewport copy + mip-gen* — flat per frame, paid once for ALL glass (triggered when any material samples viewport textures). The big fixed cost; drop to half-res if timestamps blame it.
  2. *Chrome fragment work* — coverage × taps. Toolbars/docks cover ~5–15% of screen; at 3 dispersion taps + 1 mip tap + analytic SDF/normal math, comfortably sub-millisecond on M-series. Evidence class: [Zed/GPUI runs whole-window SDF-primitive UIs at 120fps on Metal](https://zed.dev/blog/videogame) ([pipeline](https://zed.dev/blog/120fps)); [Warp reports 60fps+ at 4K](https://www.warp.dev/blog/how-to-draw-styled-rectangles-using-the-gpu-and-metal) with the same primitive approach.
  3. *Draw calls* — instanced quads, one mesh per material family ([uikit's rule](https://pmndrs.github.io/uikit/docs/advanced/performance): draw calls scale with material classes + font families; MSDF text batches per font).
- **Hard rules:** no per-panel FBOs (drei-style per-material `buffer` is the anti-pattern); no `gaussianBlur` node per panel (double pass each — use mip LOD); no shader loops >6 iterations (Maxime's warning); opaque panels (metal/ceramic) must NOT set `transparent`/backdrop — only glass pays the sampling tax; clamp DPR to 2; pointer/hover via direct uniform writes, never React re-render.
- **Escape hatch:** non-refractive chrome that hasn't changed can be cached to a small render target and composited as one textured quad — valid for ceramic/metal docks, invalid for live glass (refraction must resample every frame).

## Recommended composite (what to actually build)
One instanced "chrome slab" system: CSS-pixel ortho group parented to camera; DOM twins for layout+input; instanced rounded-rect quads carrying `(rect, radii vec4, borderPx, styleId)`. Single TSL node graph on `MeshPhysicalNodeMaterial`: SDF → `fwidth` AA into `opacityNode`; SDF-gradient bevel into `normalNode`; bevel profile doubles as `thicknessNode`; per-style branch: glass = `backdropNode` with `viewportSafeUV` edge-lensing + 3-tap dispersion + `viewportMipTexture` LOD frost + Beer–Lambert tint; metal = anisotropy 0.8 + pointer PointLight streak; ceramic = clearcoat 1. Evan-Wallace analytic shadow quad underneath. Everything above is FITS-TSL except the uikit/drei architectures (reference only, ADAPT) and DOM-snapshot glass libraries (ADAPT/rejected).
